# Project 15: Automate Server Config with Ansible

## Objective
Use Ansible for remote configuration automation: set up an Ansible controller and install/configure a web server on remote Linux servers with a playbook (no manual SSH configuration on the servers).

## Setup
- Ansible controller: the Ubuntu 24.04 Linux VM used for previous projects
- Managed nodes: 2 x Amazon Linux 2023 EC2 instances (`t3.micro`) provisioned by Terraform
- Region: ap-south-1 (Mumbai)
- Web server: Apache (`httpd`) installed and configured only by Ansible
- Access: SSH (port 22) allowed only from the controller's public IP; HTTP (port 80) public

## Architecture
```
Ubuntu VM (Ansible controller)
   |  SSH (key: project15-key.pem)  -- ansible-playbook webserver.yml
   v
VPC 10.15.0.0/16 -> public subnet 10.15.1.0/24
   +-- shivam-project15-web-1 (Apache)  <-- HTTP 80 -- Internet
   +-- shivam-project15-web-2 (Apache)  <-- HTTP 80 -- Internet
```

## Project Structure
```
project15-ansible-server-config/
├── terraform/
│   ├── providers.tf              # AWS, TLS, local, http providers

│   └── templates/inventory.tftpl # Ansible inventory template

    ├── inventory.ini             # (generated by Terraform, git-ignored)
    └── project15-key.pem         # (generated by Terraform, git-ignored)
```

## Implementation Steps (run on the Linux VM)

### 1. Pull the latest code and verify AWS access
```bash
cd ~/aws-terraform-capstone
git pull
aws sts get-caller-identity
```

### 2. Set up the Ansible controller
```bash
sudo apt update
sudo apt install -y ansible
ansible --version
```

### 3. Provision the managed nodes with Terraform
Terraform also generates the SSH key (`ansible/project15-key.pem`) and inventory (`ansible/inventory.ini`).
```bash
cd ~/aws-terraform-capstone/project15-ansible-server-config/terraform
terraform init
terraform fmt -check
terraform validate
terraform plan -out=tfplan
terraform apply tfplan
```

### 4. Verify controller -> node connectivity
Wait ~1 minute for the instances to boot.
```bash
cd ../ansible
cat inventory.ini
ansible all -m ping
```
Expected: `web1 | SUCCESS` and `web2 | SUCCESS` with `"ping": "pong"`.

### 5. Confirm no web server exists yet
```bash
ansible webservers -m shell -a "rpm -q httpd || true"
```
Expected: `package httpd is not installed`.

### 6. Install the web server using the playbook
```bash
ansible-playbook webserver.yml --syntax-check
ansible-playbook webserver.yml
```
Expected: `PLAY RECAP` shows `failed=0` for both hosts, and the verify play returns HTTP 200.

### 7. Show idempotency (optional)
```bash
ansible-playbook webserver.yml
```
Expected: `changed=0` for both hosts.

### 8. Verify the web server
```bash
ansible webservers -m shell -a "systemctl is-active httpd"
terraform -chdir=../terraform output web_urls
curl -s http://<node-public-ip> | grep "<h1>"
```
Open both URLs in a browser; each page shows its own hostname and private IP.
